R2 — Fixed-neighbor future-path modes

Purpose: take each already certified set of historical analogues and show whether their observed futures formed one coherent path or several recurring continuation/failure paths. R2 does not search again, rename chart patterns, or train a predictor.

Claim boundary: R2 is a descriptive view of consumed historical outcomes. It cannot authorize a probability, expected return, trading rule, recommendation, or production promotion. M2 remains the only prospective claim path, and M2 is correctly waiting for a post-freeze source refresh.

R2-00 contract to freeze before opening real paths

  1. Primary members: preserve ranks 1–20, separate matches with matched_symbol == query_symbol, then retain only the lowest original rank for each remaining matched symbol. Display excluded and censored rows with reasons.
  2. Horizon: mode discovery uses sessions 1–60. A member is complete only when all 60 expected sessions exist, timestamps match the stored expected calendar, and both the selected path channel and its source bindings are valid. No interpolation, forward fill or survivor substitution is permitted.
  3. Views: run two separately labelled analyses: cumulative close return and cumulative benchmark-relative close return. Never blend the two into one score. ATR-normalized, high/low and 126-session data remain visible supporting evidence, not hidden clustering degrees of freedom in R2-v1.
  4. Path distance: mean absolute pointwise difference over the fixed 60 cumulative-return observations. This transparent metric is robust to a single extreme step and introduces no learned parameters. All arithmetic uses float64 with deterministic lexicographic tie-breaking by (original rank, episode_id).
  5. Clustering: deterministic Partitioning Around Medoids for k=1..min(4,floor(n/3)). A displayed multi-mode result must have at least three complete primary members per mode. Every medoid is an actual historical path.
  6. Separation: a multi-mode candidate requires mean silhouette at least 0.25. Among qualifying stable candidates, select the greatest silhouette; ties within the frozen numeric tolerance choose smaller k, then lexicographically smaller medoid identities.
  7. Stability: use 256 deterministically seeded matched-cutoff calendar-quarter block bootstraps. Refit weighted PAM to sampled blocks, assign all base members to bootstrap medoids and compare with base labels. At least 205/256 replicates must be valid and median adjusted Rand index must be at least 0.80. Report the full validity count and ARI distribution.
  8. Fallback: if no multi-mode candidate passes size, separation and stability, report one medoid and one cohort envelope. If fewer than three complete primary members exist, abstain from modes. Never force k>1.
  9. Mutation firewall: changing future values may change medoids, memberships and descriptive summaries—that is R2's purpose—but must leave upstream seals, raw retrieval ranks, primary-member identities and every outcome-blind selection byte-identical.

Preflight caveat: the exact calendar-block construction and availability of a defensible outcome-blind context contradiction must be measured in R2-00. If verified point-in-time context is absent, the product must say unavailable; it must not invent a negative analogue or sector/regime slice.

R2-04 single-copy engineering design IMPLEMENTED; GATE PENDING

The selected implementation directly dictionary-decodes the ten required columns into one approximately 321-MiB Arrow image in the parent, validates that all 56,325 path-bearing episodes are physically contiguous, and indexes each episode to one constant-time slice. Twelve fork workers inherit those read-only pages; no worker opens the Parquet path store.

The pre-run engineering gate uses the authentic 6,917,999-row input and twelve forks, but computes no real mode result. It requires exact serial/fork result and partition bytes, recovers simulated crash-left staging, reuses a completed prefix without changing its bytes, and quarantines/refuses a damaged complete partition. Frozen bounds are 512 MiB for Arrow buffers and 2 GiB parent peak RSS. Only an independently verified gate may authorize the full R2-04 build.

Final evidence panel

Each query shows the version-pinned cohort handle; all 20 raw analogues; primary/excluded/censored membership; the selected absolute and benchmark-relative mode count; actual medoid charts; member lists; frequency; median and interquartile path envelopes; 5/20/60-session return, MFE, MAE and barrier summaries; stability/separation diagnostics; and a clear disagreement banner when stable modes differ materially.

Context slices may appear only with verified point-in-time fields and must show the unsliced fixed cohort beside each slice, effective sample size, calendar-block interval and multiplicity-adjusted exploratory decision. The current evidence contract says sector, regime and event-cluster histories are unavailable, so absence is the default.

Language: “Among these fixed historical analogues, these future paths occurred.” Never: “the stock will follow this mode,” “80% confidence,” “expected profit,” “buy/sell,” or a trader pattern name asserted as truth.

Performance, restart and audit requirements

  • Read the 272.6 MB path store once into a query-addressable episode layout; do not rescan it 3,270 times.
  • Partition deterministically by sorted query ID. Use up to 12 available cores only after single-process correctness; worker count is an execution setting and may not affect bytes.
  • Write each partition to a sibling temporary directory, fsync, hash and atomically rename. Store RUN_STARTED, per-partition receipts, COVERAGE and final create-only SEALED.
  • On restart, validate and reuse matching completed partitions, quarantine conflicts, and compute only missing work. A complete sealed store is immutable.
  • Record wall time, CPU time, peak resident memory, read volume and per-stage timing. Performance is accepted only after exact correctness; there is no artificial low-memory target.

Definition of complete

R2 is complete only when R2-00 through R2-06 pass in order, the independent verifier reconstructs every query, the HTML parser and relevant/full test suites pass once at their appropriate checkpoints, Git and artifact identities are recorded in the running log, and the output still carries false predictive/trading authorization. Until then, the currently released retrieval and evidence-card system remains the authoritative end-to-end result.
