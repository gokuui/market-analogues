L-001 — Standalone market-agnostic foundation

What: Created canonical CSV/Parquet directory and long-table adapters, quality audit, causal episode construction, benchmark alignment, representations, exact distance, outcomes and HTML reporting.

Why: Existing NASDAQ/NSE repositories are data providers, not a suitable home for a reusable analogue engine. Source data must remain read-only and derived artifacts isolated.

How: Normalized the input contract to timestamp/open/high/low/close/volume plus symbol, used dataset configuration rather than market-specific branches, and wrote artifacts beneath a configured output directory.

Verification: Adapter canonicalization, quality rules, scale invariance, causal episode boundaries, context alignment and report tests.

L-002 — Research and prior-art incorporation

What: Compared chart-pattern literature, time-series similarity papers, DTW/ShapeDTW, matrix-profile/MASS approaches, public stock matchers, aeon, tslearn and UCR baselines.

Why: Reuse validated ideas and avoid rebuilding known methods without knowing their limitations.

How: Adopted streaming candidate generation, optional MASS acceleration, bounded DTW, overlap exclusion, structural events, method comparison and outcome summaries. Kept generic time-series baselines separate from the financial metamorphic oracle.

Decision: No inspected repository supplied the complete requested combination of professional-chart context, causal controls, exact reranking, outcome separation and market-agnostic ingestion. Ideas were incorporated without copying incompatible code.

Detailed sources and comparisons remain in research evidence and repository comparison.

L-003 — Verified exact metric baseline

What: Locked a composite distance over coarse, stage, price/DTW, candle-volatility, volume-shock, market-context and structural components.

Why: The representation must preserve the stock’s development and market context while remaining price-unit and volume-unit invariant.

How: Precomputed resampled representation arrays, stage and structural signatures; reused exact scores through selection; kept forward outcomes strictly outside retrieval.

Evidence: Synthetic retrieval passes at recall@10 0.953846 and nDCG@10 0.935744 with zero critical-negative errors and zero future-mutation delta.

Rejected: Simple metric reweighting and a single dense weighted proxy reduced synthetic or candidate evidence, so the stable metric was restored.

L-004 — Complete-universe baseline measurement

What: Added deterministic serial/parallel scans, explicit failure accounting, coverage reconciliation, memory/time metrics and pool-saturation reports.

Why: Passing unit tests or a few symbols cannot establish complete-universe behavior.

How: Scanned every quality-eligible symbol at stride five and reranked a bounded pool. Used observed query sessions for the 60-bar gap.

Evidence: NSE scanned 1,843 instruments and 1,040,155 windows in 92.61 s at 436 MB. NASDAQ scanned 11,584 instruments and 3,786,156 windows in 203.49 s at 453 MB. Zero eligible-symbol failures.

Failure retained: pool-500 recall versus pool 1,000 was only 0.75 NSE and 0.65 NASDAQ; coarse/exact Spearman was 0.145 and 0.080. Gate 08 remains failed.

L-005 — Stratified exhaustive sampled oracle

What: Built Gate 09 to exactly score every candidate in deterministic market/quality/liquidity/time samples and persist full component rankings.

Why: Comparing pool 500 to pool 1,000 only measures saturation against another approximate pool. A locked exact target is required to reason about recall.

How: Measured recent median dollar volume for all A/B instruments; selected deterministic low/middle/high strata; sampled episodes across eligible history; scored all with the exact composite; explicitly marked post-overlap-deduplication oracle membership/rank; persisted digests and Parquet rankings.

Evidence: NSE 12/12 cases, 3,192 episodes, 24 stratified instruments. NASDAQ 12/12 cases, 2,658 episodes, 18 stratified instruments. Zero temporal, duplicate, non-finite or top-k failures.

L-006 — Deterministic multiview fusion

What: Added independent coarse, price-shape, 12-stage development, candle-volatility, volume-shock, market-context and structural candidate views; local per-symbol quotas; stable reciprocal-rank fusion; cached/versioned oracle view distances; and a reusable Gate 10 command/report.

Why: Raw distances have incompatible scales, and one weighted proxy can bury a strong match visible in only one professional-chart view.

How: Converted each smaller-is-better view to deterministic ranks, guaranteed view representation, deduplicated candidates, then exact-reranked. Stable candidate IDs break all ties. Serial/parallel and shuffled-input tests assert determinism.

Iterations: Cheap v1 failed badly: only 1/12 NSE and 3/12 NASDAQ at pool 125, worst recall 0.60/0.75. v2 added a multichannel coarse view and aligned stage development with the exact 12-stage structure. At pool 125 it still failed 4 NSE and 1 NASDAQ cases. Pool 175 is the first tested pool to clear 0.95 in every sampled case.

Evidence: Gate 10 passes 12/12 per market at a worst-case recall of 0.95. Failed attempts remain under gate history.

L-007 — Full-universe multiview smoke and stop decision

What: Ran one 252-bar current query over each complete quality-eligible universe with multiview scanning and exact reranking of pool 1,000. Runs executed concurrently and wrote separate smoke reports without overwriting Gate 08.

Why: A calibrated sampled pass must not be promoted without whole-market fidelity and performance evidence.

Evidence: NSE: 1,843 instruments, 1,040,155 windows, 130.56 s scan, 311.71 s total, 458 MB peak, pool-175 versus pool-1,000 recall 0.40. NASDAQ: 11,584 instruments, 3,786,156 windows, 791.27 s scan, 902.61 s total, 757 MB peak, recall 0.50. Both had zero scan/build failures.

Interpretation: Memory and coverage are sound. Latency and shortlist saturation fail. Pool 1,000 is not exhaustive, so even these recall numbers are not completeness guarantees.

Decision: Keep multiview opt-in. Stop approximate weight tuning. Proceed to persisted view shards and mathematically safe progressive exact scoring before independent Gate 12.

L-010 — Full NASDAQ 252 layer, adaptive precision and persisted-oracle gate

What: Extended Gate 11A to the complete NASDAQ 252-bar universe and added a separate oracle mode that evaluates the persisted signature contract rather than assuming the earlier on-demand cheap-v2 result transfers.

Incident: The first full build emitted a float16 overflow warning on an extreme-but-finite signature. Continuing would have produced a rejected shard and failed manifest, so the run was interrupted. Completed shards were atomic and remained reusable.

Resume ran with corruption-aware repair, reused 8,583 completed shards, built/repaired 3,001 remaining shards, and produced a complete manifest. Exactly one of 11,584 final shards required float32.

Full NASDAQ evidence: 11,584/11,584 eligible shards, 3,823,301 stored rows, 496 quality exclusions, zero failures, 148.12-second resumed completion, 1.6 GB disk. Decision: The 252-bar persisted candidate layer is correct enough to proceed to exact-safe scoring. L-011 — Gate 11B first exact-safe progressive scorer

What: Split exact representation scoring into a non-DTW lower-bound phase and a completion phase. Added a constraint-aware progressive scorer that orders candidates by the safe bound, maintains the current overlap/per-instrument-aware top-k threshold, and skips DTW only when a candidate cannot beat that threshold. Added an optional symmetric multivariate LB_Keogh bound inside the same Sakoe–Chiba band.

Why: Persisted candidate generation is now fast enough, but building representations and exact-reranking pool 1,000 remains the dominant end-to-end cost. All composite weights and component distances are non-negative, allowing a formal partial-sum lower bound without changing the metric.

Safety argument: The default bound includes every exact non-DTW component and 55% rigid price contribution; the omitted DTW contribution is bounded by zero. Candidates are processed in ascending lower-bound/episode-ID order. Once a future bound is strictly greater than the worst currently selected exact match, it cannot enter a full feasible top-k. Strict comparison preserves ties. Optional LB_Keogh sums per-point multichannel deviations outside the allowed envelope and divides by the maximum possible path length, remaining below normalized DTW.

Differential evidence: Synthetic family and overlap-heavy tests return identical IDs and distances for brute force, default pruning and stronger LB pruning. On current 252-bar oracle cases, default zero-DTW pruning returned identical rankings: NSE pruned 212/304 and reduced 3.30 to 2.38 seconds in the first run; NASDAQ pruned 120/224 and changed 3.44 to 3.26 seconds. The stronger LB version reduced exact DTWs to 60/304 on NSE and 94/224 on NASDAQ.

Rejected default: Eager/automatic LB_Keogh was not consistently faster. In a later concurrent run it improved NSE 3.35→2.07 seconds but slowed NASDAQ 2.47→2.92 seconds. It remains opt-in; the zero-DTW bound is the default until a measured policy justifies LB overhead.

Limits: This is a correctness-first implementation over an already materialized candidate list. It has not yet run differential checks over all 24 Gate 09 cases, does not avoid raw candidate representation construction, and is not yet wired into the user-facing search command.

L-012 — Gate 11B full sampled-oracle differential

What: Added a reusable verify-pruning command, immutable gate record and readable HTML report. It reconstructs every candidate in each persisted Gate 09 case, runs the default non-DTW partial bound and the optional symmetric multivariate LB_Keogh bound, and compares both outputs with the stored exhaustive authority.

Why: Two real examples and synthetic tests were insufficient to call pruning exact-safe. The optimization must preserve ordered episode IDs, total distance and every explainable component across markets, lookbacks, historical/current cutoffs, quality tiers and liquidity strata.

How: Candidate episode IDs and windows are reconstructed from the locked oracle Parquets and source data. The verifier uses the same 60-session gap, overlap deduplication, per-instrument cap and top-k as the oracle. A case passes only when ordered IDs are identical and totals/components agree within 1e-12. It separately records eligible count, exact evaluations, safe prunes, bound evaluations and scoring time.

Correctness evidence: NSE passed 12/12 cases over 3,192 candidates; NASDAQ passed 12/12 over 2,658. Both modes reproduced all 24 oracle rankings. Maximum total-distance delta was 4.440892098500626e-16; maximum component delta was zero.

Work avoided: Default pruning evaluated 1,045/3,192 NSE candidates and 966/2,658 NASDAQ candidates, safely avoiding 67.26% and 63.66% of exact evaluations. LB_Keogh evaluated 781 and 841, avoiding 75.53% and 68.36%.

Performance decision: Default aggregate scoring took 23.39 s NSE and 22.11 s NASDAQ. LB_Keogh took 22.73 s and 22.46 s. The stronger bound reduces exact DTW work but is not consistently faster, so D-008 keeps it opt-in.

Regression evidence: The complete suite passes 72/72 tests in 25.39 seconds; measured source coverage is 88%. Both generated Gate 11B JSON records parse successfully, both HTML reports were written, documentation HTML parses, and git diff --check is clean.

Limits: The verifier measures the scorer after candidate representations are materialized. User-facing search still uses the older exact reranker, and the complete exchange is not an exhaustive exact candidate set. Next integrate persisted view retrieval with the verified pruned reranker, then build an independent Gate 12 matrix.

L-014 — Constrained-pruning threshold correction

Finding: Planning an exhaustive Gate 12 reference exposed an adversarial case absent from the 24 sampled oracles. Suppose A and B initially fill top-2. A later, cheaper C overlaps both, so greedy overlap selection now contains only C and requires farther non-overlapping D. The scorer recomputed the selected set but retained the old A/B finite threshold when the set became incomplete; D could therefore be stopped even though it was required.

Fix: After every exact evaluation, set the bound threshold to the worst selected distance only when the constrained result contains top_k matches. If overlap deduplication or an instrument cap leaves fewer than top_k, reopen the threshold to infinity until the result is full again. This preserves the safe stopping proof: every candidate capable of changing the complete constrained prefix has been evaluated before a finite frontier can stop the scan.

Regression: Added the explicit A/B/C/D overlap topology. The old implementation would return only C; the corrected scorer evaluates D and returns C,D. This test is independent of financial feature values and directly exercises the control-flow invariant.

Gate 11B rerun: All 12 NSE and 12 NASDAQ exact-oracle cases still pass with maximum total delta 4.44e-16 and zero component delta. Work counts are unchanged: default prunes 2,147/3,192 NSE and 1,692/2,658 NASDAQ candidates; optional LB_Keogh prunes 2,411 and 1,817.

Gate 11C rerun: Schema-v3 RELIANCE digest remains 0badb2446edfcdaec2da97f6551324b8959c8583ad845511d3ca22aa3928ed4a; worst repeated time 29.05 s and peak 476.02 MB. AAPL remains 371e51e49ae7934bc8ae580b8439787fc67169c6dc344a143136bf053681e26c; worst 76.23 s and 772.26 MB. Both have zero repeat delta and the same 97/175 and 88/175 prune counts.

Decision: Supersede the incomplete threshold rule described in L-011 with the reopen-on-incomplete invariant above. Keep the broader Gate 12 claim open: passing known cases did not substitute for adversarial reasoning here.

L-015 — Gate 12 exhaustive-reference plan and independent registry rule

L-017 — T12-01 exact-storage feasibility and architecture lock

What: Added a market-agnostic feasibility verifier, CLI command, machine gate and HTML report. It samples deterministic windows from all 12 locked symbols, serializes native, float32 and float16 layouts, reloads them, and differentially checks every representation field, exact non-DTW lower bound, lower-bound components, rigid-price term, completed total/components and candidate ordering.

Why: The planning estimate treated all 1,353 numeric values as float32. Inspection and measurement show the actual exact contract is mixed precision: the 128 coarse values are float32, but 1,225 channel/stage/structural values are float64. Choosing a store from the lower estimate could silently lose exactness or exhaust disk.

How: The versioned compressed probe stores 19×48 and 4×64 optional samples with 23 presence flags, 48 stage values, 9 structural values and the 128-value coarse vector. The loader validates schema, shapes, row counts and a content digest. The CLI revalidates both frozen registries against current stock, benchmark and quality fingerprints; checks YAML/Parquet identity; verifies current view-manifest digests against their gates; and derives the complete 4,884,685-row projection from those manifests.

Evidence: Forty-eight representations (four windows for each of six NSE and six NASDAQ symbols; label digest 7f97ad7856525141622389ef00313312942852c5e4ac46e24ab07d4acdc1171a) were measured. Native is bit-exact for all fields and produces zero lower-bound, component and total delta. Its sample-compressed footprint is 9,287.58 bytes/row; with the preregistered 1.25 safety factor the store projects to 56,708,648,743 bytes (52.81 GiB). The 64-byte/row frontier adds 312,619,840 bytes (0.29 GiB).

Reduced-precision rejection: Float32 projects to 29,121,626,973 bytes (27.12 GiB) but changes fields by up to 2.84e-6, completed totals by 6.81e-8 and components by 3.03e-7. Float16 projects to 14,976,266,122 bytes (13.95 GiB) and changes totals by 4.06e-4 and components by 2.76e-3. Rankings happened to agree in this small probe, but both layouts fail the fixed 1e-12 authority requirement and cannot be promoted.

Resource decision: Free space at the final gate was 10,179,444,736 bytes (9.48 GiB), of which 5 GiB must remain reserved. A lossless store plus frontier would need 57,021,268,583 bytes. Gate 12B therefore passes by selecting two_pass_streaming, as explicitly allowed by T12-01; it does not build the infeasible store.

Tests and visible failure: Tests cover missing optional context, constant arrays, extreme finite values, native equality, reduced-precision detection, corrupt/truncated payload, version mismatch and invalid resource controls. The complete regression passes 88/88. The first real command used unavailable /usr/bin/time and exited 127 before any work; the shell-timed retry completed in 6.09 seconds. A diff audit then found that distance comparisons were concentrated at the start of the sample; before commit they were spread across positions 0,15,31,47 and eight disjoint candidates spanning both exchanges, layout validation was strengthened, and the final gate passed in 7.02 seconds. T12-02 vectorized exact lower-bound work is next; no Gate 12 recall has been measured.

L-018 — T12-02 vectorized exact lower-bound kernel

What: Added a market-independent sliding exact-representation kernel and vectorized lower-bound comparison. It reproduces the scalar 128-value float32 coarse vector, 19×48 optional samples, 4×64 DTW samples, 48 stage values, 9 directional-event structural values, missing-channel masks and every non-DTW component. Configurable chunking bounds memory without changing positions or results.

How: Sliding OHLCV windows are processed as matrices. Rolling mean/extrema and the two-stage robust median/MAD transforms operate across windows; interpolation retains the scalar missing-data rule; benchmark path/drawdown/relative channels reset causally inside each episode; stage blocks and structural directional events are evaluated in batches. Lower-bound groups use the identical pairwise robust scale, float32 coarse evaluation order and configured weights.

Correctness: Full, partial and absent benchmark context, constant price, zero volume, future benchmark mutation and whole-versus-chunked runs match scalar fields within 1e-12. Across the real gate, maximum total delta is 8.88e-16 and maximum component/rigid delta is 3.55e-15. Tests caught and corrected two float32 operation-order differences in coarse distance and an initial vectorized structural-loop axis error before the gate.

Failed performance attempt retained: The first 12-symbol run used a single cold timing. Aggregate speedup was 25.15× and RSS 352 MB, but CAKE, homefirst and onwardtec measured only 18.94×, 17.41× and 18.43×, so Gate 12C failed. The 20× threshold was not reduced.

Final benchmark protocol and evidence: Warm a ten-window batch, then use the median of three complete batch timings to reduce cold-start/noise bias; the scalar reference remains a full online representation plus lower bound for every window. All 12 frozen symbols and 1,200 windows pass individually: minimum speedup 20.5536×, aggregate 25.0741×, peak RSS 373.99 MB against the 512 MB limit. Final wall time was 61.46 seconds.

Decision: T12-02 passes. Proceed to T12-03’s resumable frontier and constrained two-pass exhaustive authority. No independent Gate 12 recall has yet been measured.

L-019 — Float16 behavioral audit and two-tier precision policy

Prompt and correction: The user challenged whether 1e-12 accuracy was necessary and asked to use float16 if it was sufficient. That challenge is correct for practical retrieval: twelve decimal places are not a meaningful product requirement. They remain valuable only for internal scalar-versus-optimized parity and safe-reference proofs.

What was tested: Added a reusable float16 precision verifier, CLI command, machine gates and HTML reports. For every Gate 09 case, keep the query native, quantize all candidate representation fields to float16, run the complete composite distance and constrained top-20 selection, then compare membership, order, graded nDCG and numeric drift against the persisted native oracle.

Evidence: NSE passes 12/12 cases and 3,192 candidates: minimum recall 1.0, minimum graded nDCG 0.9999924999, 11/12 exact orders, maximum total delta 0.0035484, component delta 0.0246707. NASDAQ passes 12/12 and 2,658 candidates: recall/nDCG 1.0, 12/12 exact orders, total delta 0.0043553, component delta 0.0190371. The sole difference swapped ranks 16/17 in TCS current 126; top-20 membership did not change.

Resource check: Float16’s safety-adjusted full-store projection remains 14,976,266,122 bytes. Adding the 312,619,840-byte frontier and 5 GiB reserve requires about 20.66 GB versus about 10.18 GB free. It does not fit even without the reserve. Thus lowering precision would not alter T12-01’s streaming decision.

Decision: Keep and explicitly endorse float16 for approximate candidate signatures—the existing view store already defaults to float16 and promotes only overflow shards to float32. Permit float16 for a future approximate cache if it passes recall 1.0 and graded nDCG ≥0.999 on untouched cases, followed by native reranking. Keep native precision for the streaming exhaustive authority because float16 changes ordering and its rounded lower bounds are not proven safe for the native metric. No user-visible report should imply that twelve-decimal distance precision is financially significant.
