Logging rule: add an entry before each material checkpoint commit. Never rewrite a failed result into a pass; later entries may supersede a decision while preserving the original reasoning.

L-001 — Standalone market-agnostic foundation

What: Created canonical CSV/Parquet directory and long-table adapters, quality audit, causal episode construction, benchmark alignment, representations, exact distance, outcomes and HTML reporting.

Why: Existing NASDAQ/NSE repositories are data providers, not a suitable home for a reusable analogue engine. Source data must remain read-only and derived artifacts isolated.

How: Normalized the input contract to timestamp/open/high/low/close/volume plus symbol, used dataset configuration rather than market-specific branches, and wrote artifacts beneath a configured output directory.

Verification: Adapter canonicalization, quality rules, scale invariance, causal episode boundaries, context alignment and report tests.

L-002 — Research and prior-art incorporation

What: Compared chart-pattern literature, time-series similarity papers, DTW/ShapeDTW, matrix-profile/MASS approaches, public stock matchers, aeon, tslearn and UCR baselines.

Why: Reuse validated ideas and avoid rebuilding known methods without knowing their limitations.

How: Adopted streaming candidate generation, optional MASS acceleration, bounded DTW, overlap exclusion, structural events, method comparison and outcome summaries. Kept generic time-series baselines separate from the financial metamorphic oracle.

Decision: No inspected repository supplied the complete requested combination of professional-chart context, causal controls, exact reranking, outcome separation and market-agnostic ingestion. Ideas were incorporated without copying incompatible code.

Detailed sources and comparisons remain in research evidence and repository comparison.

L-003 — Verified exact metric baseline

What: Locked a composite distance over coarse, stage, price/DTW, candle-volatility, volume-shock, market-context and structural components.

Why: The representation must preserve the stock’s development and market context while remaining price-unit and volume-unit invariant.

How: Precomputed resampled representation arrays, stage and structural signatures; reused exact scores through selection; kept forward outcomes strictly outside retrieval.

Evidence: Synthetic retrieval passes at recall@10 0.953846 and nDCG@10 0.935744 with zero critical-negative errors and zero future-mutation delta.

Rejected: Simple metric reweighting and a single dense weighted proxy reduced synthetic or candidate evidence, so the stable metric was restored.

L-004 — Complete-universe baseline measurement

What: Added deterministic serial/parallel scans, explicit failure accounting, coverage reconciliation, memory/time metrics and pool-saturation reports.

Why: Passing unit tests or a few symbols cannot establish complete-universe behavior.

How: Scanned every quality-eligible symbol at stride five and reranked a bounded pool. Used observed query sessions for the 60-bar gap.

Evidence: NSE scanned 1,843 instruments and 1,040,155 windows in 92.61 s at 436 MB. NASDAQ scanned 11,584 instruments and 3,786,156 windows in 203.49 s at 453 MB. Zero eligible-symbol failures.

Failure retained: pool-500 recall versus pool 1,000 was only 0.75 NSE and 0.65 NASDAQ; coarse/exact Spearman was 0.145 and 0.080. Gate 08 remains failed.

L-005 — Stratified exhaustive sampled oracle

What: Built Gate 09 to exactly score every candidate in deterministic market/quality/liquidity/time samples and persist full component rankings.

Why: Comparing pool 500 to pool 1,000 only measures saturation against another approximate pool. A locked exact target is required to reason about recall.

How: Measured recent median dollar volume for all A/B instruments; selected deterministic low/middle/high strata; sampled episodes across eligible history; scored all with the exact composite; explicitly marked post-overlap-deduplication oracle membership/rank; persisted digests and Parquet rankings.

Evidence: NSE 12/12 cases, 3,192 episodes, 24 stratified instruments. NASDAQ 12/12 cases, 2,658 episodes, 18 stratified instruments. Zero temporal, duplicate, non-finite or top-k failures.

L-006 — Deterministic multiview fusion

What: Added independent coarse, price-shape, 12-stage development, candle-volatility, volume-shock, market-context and structural candidate views; local per-symbol quotas; stable reciprocal-rank fusion; cached/versioned oracle view distances; and a reusable Gate 10 command/report.

Why: Raw distances have incompatible scales, and one weighted proxy can bury a strong match visible in only one professional-chart view.

How: Converted each smaller-is-better view to deterministic ranks, guaranteed view representation, deduplicated candidates, then exact-reranked. Stable candidate IDs break all ties. Serial/parallel and shuffled-input tests assert determinism.

Iterations: Cheap v1 failed badly: only 1/12 NSE and 3/12 NASDAQ at pool 125, worst recall 0.60/0.75. v2 added a multichannel coarse view and aligned stage development with the exact 12-stage structure. At pool 125 it still failed 4 NSE and 1 NASDAQ cases. Pool 175 is the first tested pool to clear 0.95 in every sampled case.

Evidence: Gate 10 passes 12/12 per market at a worst-case recall of 0.95. Failed attempts remain under gate history.

L-007 — Full-universe multiview smoke and stop decision

What: Ran one 252-bar current query over each complete quality-eligible universe with multiview scanning and exact reranking of pool 1,000. Runs executed concurrently and wrote separate smoke reports without overwriting Gate 08.

Why: A calibrated sampled pass must not be promoted without whole-market fidelity and performance evidence.

Evidence: NSE: 1,843 instruments, 1,040,155 windows, 130.56 s scan, 311.71 s total, 458 MB peak, pool-175 versus pool-1,000 recall 0.40. NASDAQ: 11,584 instruments, 3,786,156 windows, 791.27 s scan, 902.61 s total, 757 MB peak, recall 0.50. Both had zero scan/build failures.

Interpretation: Memory and coverage are sound. Latency and shortlist saturation fail. Pool 1,000 is not exhaustive, so even these recall numbers are not completeness guarantees.

Decision: Keep multiview opt-in. Stop approximate weight tuning. Proceed to persisted view shards and mathematically safe progressive exact scoring before independent Gate 12.

L-008 — Initial Git checkpoint

What: Added this running log and prepared the complete source, tests, configuration examples and readable plans for the repository’s first commit.

Why: Future work needs both code-level rollback and the reasoning needed to understand why a previous approach passed, failed or was rejected.

Scope: Generated market data, large oracle Parquets, reports, gates, virtual environments and caches remain ignored. Their compact metrics and decisions are recorded here; they are reproducible from source and local datasets.

L-009 — Gate 11A persisted-view foundation and NSE 252 layer

What: Added a fixed 240-value, query-independent signature contract; atomic per-symbol compressed NPZ shards; schema/signature/storage versions; source fingerprints; content and manifest digests; deterministic layered manifests; stale-input invalidation; corruption errors and opt-in rebuild; resumable serial/parallel builds; and warm persisted candidate search.

Why: The full-universe multiview smoke recomputed seven views from raw OHLCV for every query. It was memory-safe but took 130.56 seconds on NSE and 791.27 seconds on NASDAQ before exact reranking.

How: Extracted close path, range/body, robust volume/shock, market/relative path, 12-stage development and structural features into fixed-size vectors. Vectorized all sliding-window construction per symbol. Stores use stable episode IDs and cutoff nanoseconds; queries load only matching lookback/quality shards, enforce observed-session and same-symbol overlap limits, take local per-view candidates, then apply deterministic reciprocal-rank fusion.

Correctness: Vectorized signatures match the episode reference within 2e-5. Batch and single distances agree. Float16 storage preserves every tested per-view top-10 set and stays within 0.5% / 0.005 tolerance. Tests cover round-trip, serial/parallel digest identity, incremental lookback merge, unchanged resume, corruption detection, explicit repair, safe manifest paths and deterministic temporal search.

Optimization evidence: The same 1,264-row smoke store fell from 10.56 seconds to 0.31 seconds after vectorization and kept the exact same pre-quantization content digest. Float16 reduced a 125,907-row scale sample from 95 MB to 52 MB.

Full NSE 252 evidence: 1,843/1,843 eligible shards, 1,061,384 rows, 262 quality exclusions, zero failures, 106.64-second initial build, 442 MB disk. An unchanged run reused all 1,843 shards in 5.21 seconds with manifest digest 52672c6baf48323e045e45c0dd68641ce18acd06b45001a9c7294cec9c9b2b8e. Warm query candidate generation over 1,040,117 eligible rows took 13.63–15.54 seconds and returned pool 1,000, versus 130.56 seconds raw-on-query.

Limits: This checkpoint covers only NSE lookback 252. Persisted candidate generation does not solve the 1,000-candidate exact-rerank cost or prove exhaustive recall. NASDAQ 252, other lookbacks and exact-safe pruning remain open.
