The finished version-one system

Given a stock and an after-close cutoff, the system reconstructs exactly what was observable, searches only eligible earlier episodes, returns diverse historical developments with an explainable similarity breakdown and alignment, then separately shows what happened afterward with censoring and uncertainty.

Release claim: “These are historically similar chart developments under a declared representation.” It will not claim a named setup, forecast, trade instruction, or causal market law.

Input

Stable security identity, cutoff session, desired horizons, filters, and representation version.

Retrieval output

Top analogues, chart overlays, warp path, component scores, market context, data quality, and reason codes.

Outcome output

Forward path fan, drawdown/run-up, hit times, terminal events, sample size, censoring, and regime breakdowns.

Audit output

Data snapshot, episode hash, feature code version, candidate cutoff proof, index version, run ID, and all configuration.

Rules that govern every task

  1. Correctness blocks performance. A faster wrong pipeline does not proceed.
  2. Exact before approximate. Every optimized or indexed answer is measured against a small exact reference implementation.
  3. One semantic contract. Batch build, API, notebook, and UI call the same episode and distance code.
  4. Immutable evidence. Source snapshot, representation, benchmark labels, and experiment runs are versioned; no silent recomputation.
  5. No future dependency. Mutating rows after a cutoff must not change its episode or retrieval candidates.
  6. Similarity before outcome. Post-cutoff returns are inaccessible to representation selection until the relevance gate is locked.
  7. Failed experiments stay recorded. Negative results count toward data-snooping controls and prevent reinvention.
  8. A gate has an owner and evidence. “Looks fine” is not a completion criterion.

Definition of done

The project is complete for version one only when all of the following are true—not when a demo returns visually pleasing charts.

  • The primary-source evidence map and search ledger meet the research saturation rule; each adopted result has a task/test trace.
  • A dated historical query can be rebuilt from immutable source data using stable security identity and point-in-time membership.
  • The episode contains chart, volume, shocks, compression, relative movement, market/sector context, and quality masks at multiple horizons.
  • Synthetic invariance/adversarial tests and frozen blinded relevance tests pass for the locked representation.
  • Exact search is the oracle; the production index meets recall and latency budgets against it.
  • Every neighbor is temporally eligible, diverse, explainable, and tied to a reproducible run manifest.
  • Outcome data is separate, causally available, includes censored/delisted episodes, and cannot influence representation v1.
  • Failed methods and all tried configurations remain in the experiment registry.
  • Full historical replay finds zero critical leakage; clean rebuild, backup/restore, fallback, and rollback all succeed.
  • The interface states limitations plainly: similarity is descriptive evidence, not a trade recommendation or promised forecast.
The first irreversible decision is intentionally late. Data and representations remain inspectable; methods compete on a frozen relevance benchmark; only after the representation is locked do forward outcomes become part of the research view.

Recommended first implementation slice

Execute R0.1–R0.3 and D1.1–D1.5 first. Do not begin DTW, embeddings, or UI work until the data qualification gate passes. The repository’s prior ML/backtest failures make this sequencing especially important: the new system must not inherit unverified symbol histories, corporate-action handling, or survivor/outcome assumptions.
